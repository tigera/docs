# BGP configuration

A Border Gateway Protocol (BGP) configuration resource (BGPConfiguration) represents BGP configuration options
for the cluster or a specific node.
BGPConfiguration is a cluster-scoped resource.

For `kubectl` commands, you can use the aliases `bgpconfiguration.projectcalico.org`, `bgpconfigurations.projectcalico.org`, `bgpconfiguration.p`, and `bgpconfigurations.p`.

## Sample YAML

This sample sets the cluster-wide BGP defaults, advertises service IP ranges, and tags one prefix with BGP communities.

```yaml
apiVersion: projectcalico.org/v3
kind: BGPConfiguration
metadata:
  name: default
spec:
  logSeverityScreen: Info
  nodeToNodeMeshEnabled: true
  nodeMeshMaxRestartTime: 120s
  asNumber: 63400
  serviceClusterIPs:
    - cidr: 10.96.0.0/12
  serviceExternalIPs:
    - cidr: 104.244.42.129/32
    - cidr: 172.217.3.0/24
  listenPort: 178
  bindMode: NodeIP
  communities:
    - name: bgp-large-community
      value: 63400:300:100
  prefixAdvertisements:
    - cidr: 172.218.4.0/26
      communities:
        - bgp-large-community
        - 63400:120
```

## Definition

### Metadata

| Field  | Description                                   | Accepted Values                                                                                                          | Schema | Default |
| ------ | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------ | ------- |
| `name` | The name of this BGP configuration. Required. | Lowercase alphanumeric characters, `-`, or `.`. Must start and end with an alphanumeric character. Up to 253 characters. | string |         |

- The resource with the name `default` has a specific meaning - this contains the BGP global default configuration.
- The resources with the name `node.<nodename>` contain the node-specific overrides, and will be applied to the node `<nodename>`. Only `prefixAdvertisements`, `listenPort`, and `logSeverityScreen` can be overridden this way.

### Community

| Field   | Description                                                                                                                                   | Accepted Values                                                                                                                                                                                                                                                                                | Schema | Default |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ | ------- |
| `name`  | Name or identifier for the community. This should be used in [`prefixAdvertisements`](#prefixadvertisement) to advertise the community value. |                                                                                                                                                                                                                                                                                                | string |         |
| `value` | Standard or large BGP community value.                                                                                                        | For standard community, value should be in `aa:nn` format, where both `aa` and `nn` are 16 bit integers.<br/> For large community, value should be `aa:nn:mm` format, where `aa`, `nn` and `mm` are all 32 bit integers. <br/>Where `aa` is an AS Number, `nn` and `mm` are per-AS identifier. | string |         |

### PrefixAdvertisement

| Field         | Description                                     | Accepted Values                                                                                                                                                                                                                                                                                                                                                                                                                                          | Schema          | Default |
| ------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- | ------- |
| `cidr`        | CIDR for which properties should be advertised. | A valid IPv4 or IPv6 CIDR.                                                                                                                                                                                                                                                                                                                                                                                                                               | string          |         |
| `communities` | BGP communities to be advertised.               | Communities can be list of either community names already defined in [`communities`](#community) or community value of format `aa:nn` or `aa:nn:mm`. <br/>For standard community, value should be in `aa:nn` format, where both `aa` and `nn` are 16 bit integers.<br/> For large community, value should be `aa:nn:mm` format, where `aa`, `nn` and `mm` are all 32 bit integers. <br/>Where `aa` is an AS Number, `nn` and `mm` are per-AS identifier. | list of strings |         |
