# Host paths used by Calico Enterprise components

Several $[prodname] components mount directories or files from the host node.
If an admission policy, such as Kyverno or OPA Gatekeeper, limits the host paths that pods can use, it must allow these paths, or the admission controller rejects the component's pods.

The tables list the host path volumes that the operator adds to $[prodname] workloads in 3.23.
They do not include the Istio ambient components, `istio-cni-node` and `ztunnel`, which get their host paths from the upstream Istio charts.
Each table lists the host paths for one component:

- **Volume** is the volume name in the pod spec.
- **Access** is read-only or read-write. "Bidirectional" means the mount uses bidirectional mount propagation, which requires a privileged container. "Not mounted" means the volume is declared in the pod spec but no container mounts it. Policies that inspect pod volumes still see it.
- **When present** says whether the path is always there or depends on your configuration.

## calico-node

The `calico-node` DaemonSet runs on every Linux node, in the `calico-system` namespace.

| Host path | Volume | Access | When present |
| --- | --- | --- | --- |
| `/lib/modules` | `lib-modules` | Read-only | Always |
| `/run/xtables.lock` | `xtables-lock` | Read-write | Always |
| `/var/run/nodeagent` | `policysync` | Read-write | Always |
| `/var/run/calico` | `var-run-calico` | Read-write, Bidirectional in the init container | Always |
| `/var/lib/calico` | `var-lib-calico` | Read-write | Always |
| `/var/log/calico` | `var-log-calico` | Read-write | Always |
| `/sys/fs` | `sys-fs` | Read-write, Bidirectional | Always, for the init container |
| `/sys/fs/bpf` | `bpffs` | Read-write | Always |
| `/proc` | `nodeproc` | Read-only | Always, for the init container |
| `/sys/kernel/security` | `sys-kernel-security` | Read-only | Always |
| CNI binary directory | `cni-bin-dir` | Read-write | When the CNI plugin is Calico |
| CNI configuration directory | `cni-net-dir` | Read-write | When the CNI plugin is Calico |
| `/var/log/calico/cni` | `cni-log-dir` | Not mounted | When the CNI plugin is Calico |
| FlexVolume directory, plus `nodeagent~uds` | `flexvol-driver-host` | Read-write | Unless `flexVolumePath` is `None` |
| `/var/lib/calico/felix-plugins` | `felix-plugins` | Read-only | When the Linux data plane is VPP |

The CNI and FlexVolume directories depend on your platform.
See [Default CNI and FlexVolume directories](#default-cni-and-flexvolume-directories).

## CSI node driver

The `csi-node-driver` DaemonSet runs on every Linux node, in the `calico-system` namespace, unless `kubeletVolumePluginPath` is `None`.
The kubelet directory defaults to `/var/lib/kubelet`, and you can change it with `kubeletVolumePluginPath` in the [Installation resource](api.mdx#installationspec).

| Host path | Volume | Access | When present |
| --- | --- | --- | --- |
| `/var/run` | `varrun` | Read-write | Always |
| Kubelet directory | `kubelet-dir` | Read-write | Always |
| Kubelet directory, plus `/plugins/csi.tigera.io` | `socket-dir` | Read-write | Always |
| Kubelet directory, plus `/plugins_registry` | `registration-dir` | Read-write | Always |

## Default CNI and FlexVolume directories

The operator sets these directories when the Installation resource does not.
You can set the CNI directories with `cni.binDir` and `cni.confDir`, the Windows CNI directories with `windowsNodes`, and the FlexVolume directory with `flexVolumePath`.
For details, see the [Installation resource reference](api.mdx#installationspec).

| Platform | CNI binary directory | CNI configuration directory | FlexVolume directory |
| --- | --- | --- | --- |
| OpenShift | `/var/lib/cni/bin` | `/var/run/multus/cni/net.d` | `/etc/kubernetes/kubelet-plugins/volume/exec/` |
| GKE | `/home/kubernetes/bin` | `/etc/cni/net.d` | `/home/kubernetes/flexvolume/` |
| AKS | `/opt/cni/bin` | `/etc/cni/net.d` | `/etc/kubernetes/volumeplugins/` |
| RKE2 | `/opt/cni/bin` | `/etc/cni/net.d` | `/var/lib/kubelet/volumeplugins/` |
| All others | `/opt/cni/bin` | `/etc/cni/net.d` | `/usr/libexec/kubernetes/kubelet-plugins/volume/exec/` |

On Windows nodes, the CNI binary and configuration directories default to `/k/azurecni/bin` and `/k/azurecni/netconf` on AKS, `/Program Files/Amazon/EKS/cni` and `/Program Files/Amazon/EKS/cni/config` on EKS, and `/opt/cni/bin` and `/etc/cni/net.d` elsewhere.
The Windows CNI log directory is `/var/log/calico/cni`.
